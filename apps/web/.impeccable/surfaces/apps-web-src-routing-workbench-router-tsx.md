# Workbench surface brief

- Scope and mode: the complete React workbench shell and its product routes; Operate mode.
- Audience and job: Chinese ecommerce operators maintaining one product through verified facts, SKU setup and platform profiles, with later phases visible but never fabricated.
- Primary task: understand readiness and the next blocking action within seconds, then enter the correct working surface.
- Required proof/content: real product records from the local API; fact verification state; current SKU/platform availability; explicit Phase labels for unavailable financial and later work.
- Chosen direction: Operations Command Ledger. Deep-ink grouped navigation, compact product/platform context bar, a four-stage readiness rail, dense task ledger and a small attention column.
- Memorable moment: selecting a product turns the first viewport into its evidence-backed action plan rather than a generic metric dashboard.
- Constraints: preserve routes and API behavior; keep text, controls and tables semantic; use Phosphor icons; no fabricated metrics; responsive structure must keep all core actions available.
- Unresolved decisions: none for this UI pass. Task 11 will introduce the first real financial primitives after the redesign ships.
