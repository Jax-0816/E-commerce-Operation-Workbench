# Ecommerce AI Workbench

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要用户是中国电商运营人员。他们在本地电脑上围绕单个真实商品持续补全事实、规格、成本、平台资料、内容与经营决策，需要在高频、长链路操作中快速判断当前数据是否可靠、下一步该做什么，以及结果能否追溯。

## Product Purpose

Ecommerce AI Workbench 是一个 local-first、开源、AI 辅助的商品运营决策工作台。v0.1 要让用户从创建商品开始，经人工确认的商品事实、SPU/SKU、成本、竞品与 AI 策略，完成确定性定价、拼多多活动模拟、完整计算追踪和可锁定的运营方案。

成功意味着黄金路径中的每一步都真实可用、可恢复、可审计，并且不把缺失或不可靠的数据伪装成确定结果。

## Positioning

本产品以商品/SPU 为聚合根，把经过证据确认的商品事实、可替换的 AI 生成能力和确定性金融计算放进同一个可追溯工作流；它不是 ERP、订单/库存/履约系统、SaaS、多用户系统、聊天机器人外壳或平台自动操作工具。

## Operating Context

- 用户在 Windows 或开发环境中的本地浏览器使用工作台，生产模式由一个只绑定 `127.0.0.1` 的 Fastify 进程同时提供 React 页面和 `/api/v1`。
- 核心工作以商品为中心，频繁在商品事实、SKU、平台档案、成本、分析、内容、定价、活动和历史版本之间切换。
- 当前已完成商品建档、事实确认、规格/SKU 矩阵以及拼多多、淘宝、抖音三套独立平台档案；后续能力必须沿批准的分阶段计划实现。
- 拼多多是 v0.1 的完整主平台；淘宝/天猫与抖音只提供已明确支持的基础内容与视觉适配。

## Capabilities and Constraints

- 保持 pnpm Monorepo、React 19、Vite、React Router、Fastify、SQLite、Drizzle、Zod、Vitest 与 Playwright 的批准技术边界，不采用 Next.js、微服务或必须依赖 Docker 的运行方式。
- AI 只负责分析和内容生成，不得计算权威金额。金额、费率、公式、定价与活动利润必须由确定性引擎计算并给出完整 trace。
- AI 推断不能自行升级为 confirmed；敏感或确定性声明必须同时通过输入事实与输出声明双重守卫。
- 平台能力不完整时必须明确显示“当前平台此能力尚未完整实现”，不得伪造确定性结果。
- API key 不进入业务 SQLite、备份、日志、Git、快照或浏览器响应。
- 工作区和数据库必须可备份、恢复并迁移到另一台 Windows 电脑；架构和文件操作需跨平台。
- 界面是桌面优先的高密度操作工具，同时必须在窄屏保持结构可用；所有核心交互需有可访问名称、键盘焦点、加载、空、错误、禁用和成功状态。

## Brand Commitments

- 产品名称使用 “Ecommerce AI Workbench / 电商运营工作台”。
- 语气专业、直接、克制，优先解释数据状态、风险和下一步操作，不使用夸大或虚构营销文案。
- 新视觉世界采用已经批准的“运营指挥台”方向：为高频运营工作提供强层级、清晰上下文和稳定导航；它是 Operate 模式，不是营销落地页。

## Product Principles

1. 商品事实和证据先于 AI 生成。
2. 确定性计算与完整追踪先于解释性文案。
3. 平台能力必须真实，不支持就是明确不支持。
4. 本地可控、可备份和跨 Windows 迁移优先于云端复杂性。
5. 一个阶段只交付真实可用的纵向能力，并始终保持主路径可运行。

## Accessibility & Inclusion

核心工作流必须支持键盘操作、清晰焦点、语义化表格与表单、可感知状态反馈和足够的颜色对比；不能只用颜色表达确认、风险或不可用状态。中文运营术语保持一致，数据密度不能以牺牲可读性为代价。
