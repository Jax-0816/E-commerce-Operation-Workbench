## Key decisions

- Claims use explicit product/fact/key plus exact typed value/unit assertions and canonical domain renderings. No semantic/NLP matching is implied, and caller-supplied sensitivity is never trusted.
- Sensitive claims require a nonempty policy reference plus at least one policy-eligible sensitive allowed fact.
- `confirmed` can only be reached through an explicit `actorType: user` transition with actor/evidence provenance. Confirmed records cannot be updated, demoted, or deleted; changes use a new monotonically numbered revision.
- Missing facts remain in the input guard's `missing` partition and UI table.
- The repository uses conditional writes and an atomic `BEGIN IMMEDIATE` current-revision replacement. The application advances optimistic timestamps even when the wall clock is unchanged.
- Draft deletion is a conditional soft delete. It atomically restores the latest prior active revision or leaves no current revision; confirmed facts remain immutable. Revision identity is `(product, lineage, revision)` rather than `(product, key, revision)`.
- `0002_add-product-facts.sql`, journal, and snapshot were generated by pinned Drizzle Kit 0.31.10. The existing additive-generation regression continues to exercise the committed baseline.
